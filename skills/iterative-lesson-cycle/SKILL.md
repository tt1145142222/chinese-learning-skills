# Iterative Lesson Cycle

## Start from project evidence

1. Locate the active course project and inspect its existing organization.
2. Read any existing course profile, learner model, iteration log, and latest session evidence before producing new material.
3. Initialize project state from the bundled templates only when a continuous course project exists and equivalent files do not already exist.
4. Keep all course and learner data in that project. Never copy them into this global skill folder.

## Route the request

- For a new course, initialize the course profile and learner baseline.
- Before class, build the instructor-facing lesson guide from authoritative sources, the confirmed plan, and unresolved learner evidence.
- After class, reconcile the recording, final slides, notes, and observed difficulties before generating practice.
- After a check-in, classify each finding with one primary K/R/O/C/S label and issue its correction and retest.
- After correction or retest evidence arrives, review it, update the learner model and iteration log, and carry unresolved items forward.
- At a stage boundary, generate a timed test or simulation and a finite repair list.

## Non-negotiable rules

- Prefer actual class evidence over the original plan for post-class decisions.
- Include class recall, light transfer, and historical repair in each next-day practice set; adapt the proportions to evidence.
- Keep student exercises or tests, shareable answer keys, and internal analysis in physically separate artifacts.
- Do not expose collaboration mechanics or answer hints in student-facing documents.
- Never claim to have reviewed a missing, unreadable, or unprocessed recording.
- Do not close a recurring issue after one lucky correct response.
- Do not mark a cycle complete until the required correction or retest evidence has been submitted, reviewed, and written into the project state.
- Prefer a small number of complete, diagnostic tasks over repetitive volume.

## Load the needed details

- Read `references/workflow.md` only when initializing a course or moving to a different teaching phase; do not reread it within the same unchanged phase.
- Read `references/output-contracts.md` only before the first artifact type whose contract is not already established by the project or user.
- Read `references/evidence-and-quality.md` only when interpreting learner evidence, resolving conflicting sources, closing an issue, or making a readiness claim; ordinary material drafting does not require it.
- Copy templates from `assets/templates/` only when the project lacks equivalent state files; adapt labels to the course language without removing required fields.
