# Output contracts

Create only the artifacts needed for the routed phase. Whenever they are created, student material, a shareable answer key, and internal analysis must be physically separate files, not sections of one document. Adapt labels and examples to the course, but retain every required field below.

## 1. Instructor lecture guide

**Audience:** instructor or tutor.

**Required fields:** sources; lesson objectives; lesson structure; examples; diagnostic prompts; timing; expected in-class output; post-class evidence notes.

The guide must identify what evidence will distinguish actual coverage and learner performance from the original plan.

If the learner requests or will receive a lecture guide, create a learner-facing version. Remove instructor prompts, internal judgments, answer leakage, and collaboration mechanics. If both instructor and learner versions are needed, keep them in separate files.

## 2. Student exercise

**Audience:** learner.

**Required fields:** clear questions; realistic workload; time guidance; A/B/C confidence marker for each response or section; check-in format and submission deadline or trigger.

Do not include answers, answer hints, K/R/O/C/S labels, learner-model conclusions, carry-forward or next-lesson decisions, internal workflow, or collaboration mechanics.

## 3. Shareable answer key and explanation

**Audience:** learner, instructor, or tutor after the exercise process allows answers to be shared.

**Required fields:** complete solutions; marking points; required diagram features where the task requires a diagram; general misconceptions; general self-service correction actions explaining how any learner can redo, check, or verify the work.

Match every solution and marking point to its student exercise. Distinguish required diagrams from optional explanatory diagrams.

Keep correction actions general and task-based, such as reworking from a blank page, checking units or signs, substituting a result back, comparing against a rubric, or using an independent verification method. Do not tailor these actions to an identified learner or infer that a particular learner has a specific issue.

Do not include learner-specific findings, confidence interpretation, K/R/O/C/S labels, priorities, carry-forward decisions, learner-model updates, or next-lesson decisions.

## 4. Internal check-in or assessment analysis

**Audience:** instructor or tutor; do not share this internal artifact as the learner answer key.

**Required fields for each finding:** evidence; exactly one primary K/R/O/C/S label; optional qualifier; priority; correction; retest; carry-forward decision; supported `Mastery status` update; supported `Issue lifecycle` update.

Evidence must point to the original response or process whenever available. Keep the two state axes in separate fields: mastery uses only `new/developing/unstable/stable/reopen`, while lifecycle uses only `active/monitoring/closed`. A class impression alone cannot close an issue.

## 5. Next-lesson focus list

**Audience:** instructor or tutor.

**Required fields:** unresolved high-impact items before new content; supporting evidence; intended diagnostic or repair action; owner or learner grouping when relevant.

Place unresolved high-impact items before optional enrichment and new expansion.

## 6. Stage test or simulation

**Audience:** learner for the test and shareable key; instructor or tutor for the internal performance analysis and repair list.

**Required separate files:** a student test with confirmed scope, timed conditions, and mixed output formats; a shareable answer key and explanation; an internal performance analysis with evidence-linked findings and a finite repair list.

The student test must contain no answers or internal labels. The shareable key follows contract 3 and contains no learner-specific analysis. The internal performance analysis follows contract 4. State the basis for scope and timing. The repair list must be ranked, bounded, and actionable; it is not a copy of all prior notes.
