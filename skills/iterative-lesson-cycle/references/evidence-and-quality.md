# Evidence and quality rules

## Evidence priority by phase

Use the highest applicable evidence first. Lower-priority material may provide context but cannot silently override higher-priority evidence.

```text
pre-class: authoritative course sources > confirmed assessment rules > approved plan > learner history
post-class practice: actual coverage > observed class performance > learner history > original plan
check-in analysis: original response/process > correction/confidence marker > class impression
correction/retest: original correction or fresh retest response/process > confidence marker > prior performance > class impression
next iteration: unresolved high-impact issues > optional new expansion
```

## Finding labels

Use exactly one primary label for each finding; add a short optional qualifier if needed. A qualifier is not a second primary label. If two distinct issues require different primary labels, record them as separate findings.

| Label | Meaning | Evidence to seek |
| --- | --- | --- |
| K | 知识缺口 (knowledge gap): a key fact, concept, or relationship is missing or incorrect. | Original explanation or application that identifies the missing or incorrect knowledge. |
| R | 提取不稳 (retrieval instability): no-prompt recall, calling on knowledge, or spaced reappearance is unstable. | Unprompted recall, later retrieval or application, and spaced repeated performance. |
| O | 表达或组织不完整 (incomplete expression or organization): the answer's structure, sequence, or presentation is incomplete. | Original response, outline, work order, and required-format evidence. |
| C | 计算、推导、操作或作图过程错误 (calculation, derivation, operation, or diagram-process error). | Original calculations, derivation steps, operation trace, or diagram construction. |
| S | 审题、符号、单位、方向或粗心问题 (reading, symbol, unit, direction, or careless error). | Original prompt annotation, symbols, units, directions, and error pattern across work. |

## Issue closure and uncertainty

Track `Mastery status` and `Issue lifecycle` as independent axes. `Mastery status` must be one of `new/developing/unstable/stable/reopen`; `Issue lifecycle` must be one of `active/monitoring/closed`. Never put a mastery value in the lifecycle field, a lifecycle value in the mastery field, or combine both axes into one status phrase.

Set issue lifecycle to `closed` only after independent evidence shows the corrected behavior in a fresh task, condition, or item. One correct response, a correction copied from feedback, or an unverified confidence claim is not closure. Keep lifecycle `active` when correction or retest action remains, or `monitoring` when improvement has evidence but durability or closure evidence is incomplete. Update mastery separately from performance consistency. If a closed issue recurs, set mastery to `reopen` and lifecycle to `active`.

If a recording, video, submission, or process trace is missing, unreadable, or incomplete, say so plainly. Do not infer that content was taught, understood, submitted, or corrected. Use accessible evidence, mark the limitation, and define the next safe collection action.

A schedule change or deferral is not correction or retest evidence. When the required correction/retest submission is completely missing, session phase remains `awaiting correction`. When submitted evidence is incomplete, review what is present, but keep `awaiting correction` if the prescribed action is not complete. Use `cycle complete` only after the required evidence has been submitted and reviewed, the prescribed action is complete, and state/log updates are written.

## Multiple learners and source conflicts

Maintain separate learner identities, submissions, confidence markers, findings, and model updates. Aggregate class-level observations only after removing or clearly separating individual conclusions. Never transfer one learner's evidence to another learner's model.

When sources conflict, preserve both claims, identify their provenance and date, and use the phase priority order. For material conflicts that affect scope, assessment, or learner conclusions, request confirmation or defer the decision; do not reconcile by guesswork.

## Final QA checklist

Before claiming an artifact or iteration is ready, confirm all eight approved items:

1. Read the evidence required for the current phase.
2. Distinguish planned coverage from actual coverage.
3. Use both the latest learner performance and historical weaknesses.
4. Preserve the audience boundary among student material, shareable answers, and internal analysis.
5. Give every high-priority issue a concrete correction and retest action.
6. Avoid excessive, repetitive, or classroom-detached tasks.
7. For PDF, DOCX, PPTX, or any other rendered deliverable, complete the applicable format checks, rendering, and visual inspection before claiming it is ready.
8. Update the project learner model and iteration log.

Apply these additional safety gates as well:

- Keep all course and learner data in the active course project; never store it in the global skill folder.
- Mark missing or unreadable evidence explicitly and never treat it as reviewed. Preserve conflicting source claims with provenance and resolve or defer material conflicts under the evidence-priority rules.
- Keep learner identities and conclusions isolated when multiple learners are present.
- Do not close a recurring issue without independent fresh evidence. Keep unresolved issue lifecycle `active` or `monitoring` and carry it forward, even when the separate session phase is `cycle complete`.
